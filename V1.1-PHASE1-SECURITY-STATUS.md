## Baseline
- `main` is the live v1.0 baseline.
- `v1.0-stable` is the recovery branch for the v1.0 baseline.
- Phase 1 development is isolated on `v1.1-phase1`.

## Implemented
- Positive loan amount and tenure checks.
- Valid loan status check.
- Positive transaction amount check.
- Valid transaction type check.
- Valid transaction status check, including the existing `failed` status used by the application.
- One disbursement transaction per loan enforced by a partial unique index.
- Atomic loan approval/disbursement helper created as a SECURITY DEFINER function.
- Public execution revoked for the atomic helper.
- Public execution revoked for the legacy `rls_auto_enable()` helper.
- Server-side Telegram WebApp `initData` HMAC validation.
- Telegram Bot API token remains server-side.
- Persistent Supabase Auth session initialization added on the client.
- Verified Telegram identity is now bridged to the authenticated Supabase user through `telegram_identities`.
- Supabase service-role key is used only by server-side identity/admin code.

- Complete server-side admin mutation routing and regression coverage; current admin route is authenticated but direct client admin mutations still need migration to that route.
- Migrate document access to a private storage bucket and signed URLs.
- Make financial calculations authoritative on the server/database.
- Add end-to-end security/regression tests, including Auth/RLS/storage/admin authorization paths.
- Reconcile the live `telegram_identities` migration with the GitHub migration history before release.
